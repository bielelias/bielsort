## Environment

- CPU: 13th Gen Intel Core i5-1334U, 10 cores, 12 logical CPUs
- OS: Linux 6.7.0-keepos, x86-64, glibc 2.36
- Python: CPython 3.11.2
- Python compiler: GCC 12.2.0
- Native compiler: GCC 12.2.0

The machine was not isolated, CPU frequency was not pinned, and turbo behavior
was not controlled. These results characterize this environment; they are not
universal guarantees.

## Incremental peak memory

Command:

```bash
python benchmarks/memory.py -n 1000000 -r 3
```

Median of three isolated child processes per algorithm. Memory is the
incremental operating-system peak RSS after input generation.

| Case | Algorithm | Median time | Incremental peak |
|---|---|---:|---:|
| dense | `sorted()` | 0.18518 s | 11.80 MiB |
| dense | Biel new list | 0.04113 s | 41.98 MiB |
| dense | `list.sort()` | 0.17257 s | 4.20 MiB |
| dense | Biel in-place | 0.03596 s | 34.37 MiB |
| int64 | `sorted()` | 0.24419 s | 12.29 MiB |
| int64 | Biel new list | 0.06478 s | 38.22 MiB |
| int64 | `list.sort()` | 0.24175 s | 4.70 MiB |
| int64 | Biel in-place | 0.05961 s | 30.56 MiB |

BielSort traded substantially higher auxiliary memory for lower execution
time on these two favorable integer distributions.

## NumPy comparison

Command:

```bash
python benchmarks/numpy_comparison.py -n 10000 100000 1000000 -r 5
```

All NumPy sorts used `kind="stable"`. `NumPy E2E` includes conversion from
`list[int]` to `ndarray`, sorting, and conversion back to `list[int]`.
`NumPy array` starts with an existing `int64` array and returns an array, so it
represents a different API scenario.

| n | Case | `sorted()` | BielSort | NumPy E2E | NumPy array |
|---:|---|---:|---:|---:|---:|
| 10,000 | dense | 0.00188 s | 0.00038 s | 0.00069 s | 0.00040 s |
| 10,000 | int64 | 0.00122 s | 0.00047 s | 0.00066 s | 0.00040 s |
| 100,000 | dense | 0.01223 s | 0.00263 s | 0.00837 s | 0.00527 s |
| 100,000 | int64 | 0.01634 s | 0.00563 s | 0.00830 s | 0.00496 s |
| 1,000,000 | dense | 0.18747 s | 0.05257 s | 0.09432 s | 0.05881 s |
| 1,000,000 | int64 | 0.24738 s | 0.07975 s | 0.11835 s | 0.06677 s |

On this machine BielSort beat the equivalent NumPy end-to-end list operation
in every measured case. When input was already an array, NumPy was faster on
the one-million-element int64 case while BielSort was slightly faster on the
dense case. These are different input and output APIs and should not be
presented as interchangeable measurements.
